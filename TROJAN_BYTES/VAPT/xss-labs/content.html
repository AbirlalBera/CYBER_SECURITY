Understanding Cross-Site Scripting (XSS)

An interactive guide to XSS types, vulnerabilities, and protections

What is XSS?

Cross-Site Scripting (XSS) is a security vulnerability that allows attackers to inject malicious scripts into webpages viewed by other users. This can lead to data theft, session hijacking, or defacement.

Overview diagram showing how XSS works.

Types of XSS

1. Reflected XSS

Reflected XSS occurs when user input is immediately returned in the response without proper sanitization, often in search results or error messages.

Diagram of Reflected XSS attack flow.

2. Stored XSS

Stored XSS involves injecting scripts that are stored on the server (e.g., in comments or profiles) and executed when other users view the content.

Diagram illustrating Stored XSS.

3. DOM-Based XSS

DOM-Based XSS happens client-side when JavaScript takes unsanitized input and writes it to the DOM, allowing script execution.

DOM-Based XSS attack model diagram.

Vulnerabilities in XSS Types

  • Reflected: Vulnerable to phishing links with malicious payloads in URLs.
  • Stored: Affects all users viewing the stored content, high impact on forums/blogs.
  • DOM-Based: Exploits client-side scripts, hard to detect server-side.

Prevention: CSP and Security Headers

Content Security Policy (CSP) is a header that helps prevent XSS by controlling resource loading.

CSP overview diagram.

Other Security Headers: X-XSS-Protection, Content-Type Options, X-Frame-Options.
