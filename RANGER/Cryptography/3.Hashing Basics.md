# ==`Hash Functions`==

### What is a Hash Function?

A **hash function** is a one-way mathematical function that takes input data of any size and produces a fixed-size output called a **hash value**. It is designed so that the same input always produces the same output, small changes in input cause large changes in output, and it is computationally impractical to reverse the process or find two different inputs with the same hash.

### Why is Hashing Important?

**Hashing is important because it ensures data integrity and protects sensitive information without storing the original data.**

 **Integrity verification:** Hashing allows you to check whether data (files, downloads, messages) has been altered. If the hash changes, the data has changed.

**Password security:** Systems store **hashed passwords** instead of plaintext passwords, reducing damage if a database is compromised.

**Authentication:** Hashes are used to verify identities without revealing secrets.

**Efficiency:** Large data can be represented by a small fixed-size hash, making comparisons fast.

**Tamper detection:** Even a one-bit change produces a completely different hash, making unauthorized changes easy to detect.

### What’s a Hash Collision?

A **hash collision** occurs when **two different inputs produce the same hash output**.

### Why collisions are dangerous

If attackers can **intentionally create collisions**, they can:

- Bypass file integrity checks
- Forge digital signatures
- Replace trusted files with malicious ones

# Using Hashing for Secure Password Storage

Hashing is a secure method for storing passwords without keeping the actual plaintext passwords. It helps protect user credentials even if a database is compromised.

## **How Hashing Works for Passwords**

1. Instead of storing the password itself, store its **hash value**.
2. When a user logs in, hash the entered password and compare it with the stored hash.
3. If the hashes match → grant access.  
This way, the system never needs to know or store the actual password.


## **Problems with Simple Hashing**

- If two users have the **same password**, the hash will be identical for both.
- An attacker cracking one hash gains access to **multiple accounts**.
- **Rainbow tables** can be used to reverse hashes to plaintext passwords.

A **==`Rainbow Table`==** is a lookup table of hashes to plaintexts, so you can quickly find out what password a user had just from the hash.A rainbow table trades the time to crack a hash for hard disk space, but it takes time to create.

## **Protecting Against Rainbow Tables: Salting**

A **salt** is a **random value** added to a password before hashing.Each user should have a **unique salt**.The salt ensures that even if two users have the same password, their hashes are **different**.Salts **do not need to be secret**; they are stored with the hash in the database.

**Example workflow**:
```
1. Password: `AL4RMc10k`
  
2. Salt: `Y4UV*^(=go_!`
  
3. Concatenate: `AL4RMc10kY4UV*^(=go_!`

4. Hash the combined string using a secure algorithm (Bcrypt, Scrypt, Argon2, PBKDF2)

5. Store the hash and the salt in the database.
```

## **Why Not Use Encryption Instead?**

**Encrypting passwords is not ideal because** :
```
Encryption is reversible.
You must store the encryption key.
If the key is compromised, all passwords can be decrypted.
Hashing avoids this problem because it is one-way.
```

# Recognising Password Hashes

**Recognising Hash Types** : Before cracking a hash, you must determine **what type of hash it is**.
### Automated Tools

- Tools like **hashID** can guess hash types
- They are **not always reliable**
- Some hashes (e.g., MD5, NTLM) look identical

Example:

- Hash found in a **web application database** → likely **MD5**
- Hash dumped from **Windows system** → likely **NTLM**

### Where Linux Stores Password Hashes

Stored in :
```
/etc/shadow
```

Only readable by **root**.Older systems used `/etc/passwd` (insecure)

The ==`shadow`== file contains the password information. Each line contains nine fields, separated by colons (`:`). The first two fields are the login name and the encrypted password. More information about the other fields can be found by executing `man 5 shadow` on a Linux system.

```
username:encrypted_password:last_change:min:max:warn:inactive:expire:reserved
```
