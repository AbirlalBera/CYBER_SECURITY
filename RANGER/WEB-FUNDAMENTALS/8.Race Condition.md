
A **race condition attack** is when a hacker intentionally exploits this timing window to break a system’s logic. The attacker triggers multiple actions at nearly the exact same millisecond to bypass security checks that would normally stop them.

The most common form is the **TOCTTOU** (Time-of-Check to Time-of-Use) attack. This happens when a program checks a condition (like "Does this user have enough money?") but, before it can finish the transaction, the attacker changes the state so the check is no longer valid.

## Programs

A **program** is a set of instructions to achieve a specific task. You need to execute the program to accomplish what you want. Unless you execute it, it won’t do anything and remains a set of static instructions.


## Processes

A **process** is a **_program_** in execution. In some literature, you might come across the term **job**. Both terms refer to the same thing, although the term process has superseded the term job. Unlike a program, which is static, a process is a dynamic entity. It holds several key aspects, in particular:

- **Program**: The executable code related to the process
- **Memory**: Temporary data storage
- **State**: A process usually hops between different states. After it is in the New state, i.e., just created, it moves to the Ready state, i.e., ready to run once given CPU time. Once the CPU allocates time for it, it goes to the Running state. Furthermore, it can be in the Waiting state pending I/O or event completion. Once it exits, it moves to the Terminated state.

## Threads

## Race Conditions

**Race condition occurs when multiple threads/processes** access the same shared data or resource.

#### **Common Attack Scenarios**

|**Attack Type**|**How it Works**|**Real-World Example**|
|---|---|---|
|**Limit Overrun**|Bypassing a "one-time use" restriction by sending many requests at once.|Redeeming a single-use discount code 10 times by hitting the "Submit" button with 10 simultaneous requests.|
|**Double-Spending**|Tricking a system into spending the same balance twice.|Withdrawing $100 twice from an account that only has $100, because the system checks the balance for both requests before it has time to subtract the money.|
|**Privilege Escalation**|Swapping a file or permission during the tiny gap between a system's security check and its execution.|A program checks if you have access to `file_A`, but you quickly replace `file_A` with a shortcut to a sensitive system file before the program actually opens it.|

## Detecting Race Conditions

Race conditions are often invisible to business owners unless logs are specifically audited for anomalies like duplicate redemptions. To identify these vulnerabilities, penetration testers analyze system behavior under enforced controls (e.g., "use once" or "rate limits") and look for state-transition windows where timing exploits can occur.

**Commonly Targeted Controls:**

- **Redemption limits:** One-time use gift cards or coupons.

- **Voting/Rating:** Preventing duplicate entries.

- **Financials:** Withdrawing more than the available balance.

- **Throttling:** Bypassing "once every 5 minutes" restrictions.

## Mitigation Techniques

To prevent concurrent threads from corrupting shared data, developers use the following methods:

|**Technique**|**How it Works**|
|---|---|
|**Synchronization**|Uses **locks** or mutexes to ensure only one thread accesses a resource at a time.|
|**Atomic Operations**|Executes a set of instructions as a single, **indivisible unit** that cannot be interrupted.|
|**Database Transactions**|Groups operations so they **all succeed or all fail** together, maintaining data integrity.|
