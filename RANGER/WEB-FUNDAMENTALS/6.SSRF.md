**What is an SSRF?**

SSRF stands for Server-Side Request Forgery. It's a vulnerability that allows a malicious user to cause the webserver to make an additional or edited HTTP request to the resource of the attacker's choosing.


**Types of SSRF :** 

There are two types of SSRF vulnerability; the first is a regular SSRF where data is returned to the attacker's screen. The second is a Blind SSRF vulnerability where an SSRF occurs, but no information is returned to the attacker's screen.

## **What's the impact?**

A successful SSRF attack can result in any of the following: 

- Access to unauthorised areas.
- Access to customer/organisational data.
- Ability to Scale to internal networks.
- Reveal authentication tokens/credentials.

### **Defeating Common SSRF Defenses**

### 1. **Deny List Bypass (Block bad targets)**

**Blocks known dangerous hosts like `localhost` or `169.254.169.254`.**

### Bypasses:

```
Alternate localhost forms:
 
- 127.1
  
- 0, 0.0.0.0
  
- 2130706433 (decimal)
  
- 017700000001 (octal)
  
- 127.0.0.1.nip.io (DNS → 127.0.0.1)

Cloud metadata:

- Use a **domain you own** → DNS A record → 169.254.169.254
  
```


🧠 **Remember:** _Same IP, different disguise_

---

### 2. **Allow List Bypass (Only allow “good” URLs)**

Allows only URLs matching a pattern (e.g. `https://website.thm`).

```
Bypass:

- Create a malicious subdomain:

- `https://website.thm.attacker.com`
  
```

🧠 **Remember:** _Prefix match ≠ safe_

---

### 3. **Open Redirect Abuse**

Trusted domain redirects requests elsewhere.

```
Exploit:

Allowed URL:

https://website.thm/link?url=https://attacker.com
 
- Server follows redirect → attacker-controlled destination
```


🧠 **Remember:** _Trusted redirect = free SSRF_

---

## One-Line Summary

> **SSRF defenses fail when apps trust strings instead of final IP destinations.**
